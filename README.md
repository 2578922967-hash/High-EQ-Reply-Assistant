# High-EQ Reply Assistant

一个面向复杂社交场景的生成式 AI 沟通助手。项目目标是帮助用户在高压对话中生成“高情商、守边界、可执行”的回复，降低沟通失误与情绪消耗。

## 项目定位

这是一个个人作品集项目，聚焦「LLM 在真实沟通决策场景中的可控生成」问题，不是通用聊天机器人，而是面向职场与人际冲突场景的垂直工具。

## 我解决的核心问题

在现实对话中，用户常见痛点是：

- 需要快速回复，但又担心“说错话”
- 既要保持礼貌，又要维护个人边界
- 对方语气复杂（被动攻击、情绪施压）时难以组织有效表达

传统规则树难以覆盖高语境社交中的大量隐含语义，因此我采用生成式 AI 方案，并通过结构化提示工程提升输出稳定性。

## 方案设计

### 1) 系统架构

- 前端：轻量 Web 界面（HTML / Vanilla JS）
- 后端：FastAPI
- 模型接入：统一的模型调用层，支持 HKBU GenAI 与任意 OpenAI 兼容接口（当前使用阿里云百炼：Qwen 3.8 / DeepSeek V4）
- 部署：Render（配置见 `render.yaml`，早期版本部署于 Railway）

### 2) 核心机制：Context-Aware Prompt Architecture

我将“高情商回复”拆成一个可执行流程，强制模型走 System-2 风格推理链路：

1. **意图识别**：先识别对方文本中的潜在攻击性或情绪压力
2. **行为约束**：抑制模型过度道歉、过度迎合的默认倾向
3. **可控语气生成**：用户选择预设语气，并通过 Wit（机智）/ Diplomacy（圆融）/ Directness（直接）/ Empathy（共情）四个滑块微调，系统一次生成 3 条侧重点不同的候选回复（直接回应 / 情绪价值 / 边界表达）

这样用户可以保留最终决策权，而不是被单一回复绑架。

### 3) 场景沙盘推演

用户输入场景、双方角色和自己拟定的回复，系统按六步结构化输出：话语漏洞剖析 → 对方真实心理 → 多轮对话模拟 → 结局预判 → 破局策略 → 三种替换话术。

## 评估框架

为了把“高情商”从主观感受转为可比较指标，我定义了四维评估矩阵：

- **Empathy & Politeness**：是否体现同理与礼貌
- **Boundary Management**：是否有效守住边界
- **Clarity & Effectiveness**：是否表达清晰、可执行
- **Context Appropriateness**：是否符合场景中的权力关系与语境

在此基础上，用 5 分制用户问卷评估两个功能，并在相同场景下让用户盲选"直接问 AI（zero-shot 原生输出）"与本系统的回复。

## 结果与结论

共回收 18 份有效问卷（好评率 = 打 4 分或 5 分的用户占比）。

**场景沙盘推演**

| 维度 | 均分 | 好评率 |
| :--- | :---: | :---: |
| 结局推演可信度 | 4.33 | 83.3% |
| 自然度 | 4.28 | 88.9% |
| 漏洞准确度 | 4.22 | 77.8% |
| 策略修正帮助度 | 4.17 | 77.8% |

**即时高情商回复**

| 维度 | 均分 | 好评率 |
| :--- | :---: | :---: |
| 风格完成度 | 4.11 | 66.7% |
| 清晰度 | 4.06 | 77.8% |
| 场景适配度 | 3.94 | 72.2% |
| 社交有效度 | 3.78 | 66.7% |
| 自然度 | 3.61 | 66.7% |

**与原生 AI 的盲选对比**：在"幽默风趣带点自嘲"和"委婉但彻底的拒绝"两个语气场景中，用户偏好均为 50% : 50%，与直接问 AI 持平。

结论：

- 对"改写一句回复"这类任务，原生大模型本身已经足够强，单纯优化 Prompt 的边际收益有限；即时回复的"自然度"是当前最主要的短板。
- 场景沙盘推演得分明显更高，说明产品价值更多来自结构化的决策流程（找漏洞 → 推演对方反应 → 预判结局 → 给出修正策略），而不是话术本身。
- 基于以上结论，v2 将即时回复从单次 Prompt 升级为多阶段 Agent，并建立固定测试集做三方对照评测（见下一节）。

## v2 升级：多阶段 Agent 与自动评测

### 流程设计

即时回复新增 Agent 模式（`code/agent_runtime.py`），把一次生成拆成四个职责单一的角色：

1. **感知**：识别双方关系、权力位置、对方真实意图、潜台词与施压手段（道德绑架、威胁、甩锅等），评估回错话的风险
2. **策略**：确定核心目标与表达顺序，列出必须表达的要点和必须避开的雷区，规划 3 个回复角度
3. **撰写**：按策略写出 3 条可以直接发送的回复，明确禁止 AI 套话和无理由道歉
4. **评审**：从共情、边界、清晰、场景适配、自然度 5 个维度为每条回复打分并选出最优；若最优回复仍有维度低于 3 分，带着评审意见重写一轮

每一步的输出与耗时都会记录下来，前端展示分析结论、策略和每条回复的得分。"阴阳怪气"语气的目标与高情商标准相反，仍走原有单次生成。

### 评测方法

- 测试集：30 条（中文 22 / 英文 8），其中 13 条改编自真实聊天记录，覆盖催婚、借钱催债、领导施压、同事甩锅、客户压价等场景（`code/eval/testset.json`）
- 对照组：原生 AI（只告诉模型语气，不做任何设计）/ v1 单次结构化 Prompt / v2 多阶段 Agent，三者使用同一生成模型 Qwen 3.8 Max
- 评分：每个案例三个系统各 3 条回复共 9 条，打乱顺序、隐去来源后，由另一家族的模型 DeepSeek V4 Pro 按 5 个维度盲评（每项 1-5 分，满分 25）
- 脚本：`code/eval/eval_harness.py`，完整结果见 `code/eval/results/20261015-033230/`

### 评测结果

| 系统 | 首条回复 | 3 条平均 | 3 条最佳 | 平均耗时 | 模型调用次数 |
| :--- | :---: | :---: | :---: | :---: | :---: |
| 原生 AI | 19.30 | 19.39 | 21.07 | 5.8s | 1.0 |
| v1 单次 Prompt | 18.83 | 19.56 | 21.67 | 5.9s | 1.0 |
| v2 多阶段 Agent | **21.73** | **20.66** | **22.60** | 40.3s | 4.9 |

| 维度（全部回复平均） | 原生 AI | v1 单次 Prompt | v2 多阶段 Agent |
| :--- | :---: | :---: | :---: |
| 共情礼貌 | 3.69 | 3.78 | 3.76 |
| 边界守护 | 4.24 | 4.02 | 4.31 |
| 清晰有效 | 4.06 | 4.00 | 4.42 |
| 场景适配 | 3.67 | 3.69 | 4.01 |
| 自然度 | 3.73 | 4.07 | 4.16 |

- 首条回复（用户最先看到的那条）逐案对比：Agent 对原生 AI 20 胜 / 3 平 / 7 负，对 v1 22 胜 / 4 平 / 4 负
- 43% 的请求触发了评审后重写

### 结论与取舍

- v1 的首条回复得分略低于原生 AI，与真人盲选 50:50 的结论一致：只优化单个 Prompt 收益有限。
- 拆分角色并加入自我评审后，提升主要来自"清晰有效"和"场景适配"，真人问卷中最弱的"自然度"也有改善。
- 代价是耗时从约 6 秒增加到约 40 秒。后续可通过合并感知与策略步骤、分析与评审改用轻量模型、流式输出等方式压缩等待时间。
- 局限：评分为大模型自动评审且只运行一轮，可能与真人偏好存在偏差，结论仍需真人盲测进一步验证。

### 后续迭代：发现"高分回复会编借口"

实测中发现，评分高的回复常常替用户编造场景里没有的借口（如"我在加班""房租刚扣完"），推荐的拒绝回复还会留下"明年再说"之类的让步口子，长度也远超微信聊天的习惯。而原有的 5 维评分并不惩罚这些问题。

改进措施：

- **撰写**：增加三条硬性规则，即只使用消息与场景中已有的信息、拒绝时不留让步口子、长度与原消息相当（中文约 30-80 字）
- **评审**：对每条回复增加编造事实、留让步口子、过长三项一票否决，触发的回复不能被推荐；三条全部触发时强制重写，并在代码层面兜底校验
- **评测**：新增独立于 5 维打分的事实核查，由评审模型单独盲审每条回复是否编造了具体事实，同时统计字数（`--factcheck-only` 可为已有结果补充核查）

| 指标（首条回复） | 原生 AI | v1 单次 Prompt | Agent 迭代前 | Agent 迭代后 |
| :--- | :---: | :---: | :---: | :---: |
| 5 维总分 | 19.30 / 20.07 | 18.83 / 20.47 | **21.73** | 20.30 |
| 编造事实率 | 13% / 27% | 27% / 20% | 17% | **3%** |
| 平均字数 | 167 / 171 | 119 / 126 | 210 | **108** |
| 平均耗时 | 5.8s / 7.2s | 5.9s / 6.6s | 40.3s | 47.5s |

注：原生 AI 与 v1 在两轮评测中各重新生成一次，斜杠前后分别为迭代前（`results/20261015-033230/`）与迭代后（`results/20261015-043818/`）的结果。

结论：

- 迭代后编造率从 17% 降到 3%，回复长度缩短约一半，更接近真实聊天中可以直接发出的样子。
- 代价是 5 维总分回落到与基线持平，其中"共情礼貌"下降最多：评审模型倾向于给客套话更多的长回复打高分。
- 这说明单一的 LLM 评分会奖励"看起来周到"而不是"真实可用"，评测指标本身需要设计；同一系统两轮之间也有约 1 分、十几个百分点的波动，小样本结论需谨慎。

## 本地运行

```bash
cd code
pip install -r requirements.txt
# 在 code/.env 中配置：LLM_BASE_URL、LLM_API_KEY（OpenAI 兼容接口）
uvicorn backend_api:app --reload                 # 启动网页，访问 http://localhost:8000
python eval/eval_harness.py --gen-model qwen3.8-max --judge-model deepseek-v4-pro --limit 3   # 冒烟评测
```
